# Proposal

## Why

The iOS app can only be installed from Xcode onto the developer's own phone, and that install stops launching after 7 days. There is no paid Apple Developer account and none is planned, so TestFlight, Ad Hoc and the App Store are closed. The project is open source, so anyone should be able to install it on an iPhone with a free Apple ID, the same way the macOS app and the Android APK can already be built with a script.

## What Changes

- New `scripts/package-ios.sh` that builds the release app for a real device with code signing turned off and leaves an unsigned `dist/OpenAdhd.ipa`, in the style of `package-mac.sh` and `package-android.sh`.
- An AltStore/SideStore source file in the repository (`altstore/source.json`) that lists the latest IPA, so a user adds one URL and gets update prompts instead of downloading by hand. The script prints the version and size the entry needs.
- README section "Installing on an iPhone" that says what each route is and costs: AltStore, SideStore, Sideloadly, and building from source with Xcode and a free Apple ID. It states plainly that a free Apple ID signature lasts 7 days, what happens on expiry (the app does not launch, the data stays), and that Settings export is the backup.
- The README's Packaging and Version sections mention the new script and that a release raises the iOS version in `iosApp/src/Info.plist`.

Out of scope: any paid-account route (TestFlight, Ad Hoc, App Store, AltStore PAL), jailbreak and TrollStore installs, a signed IPA, CI that builds releases, and changing the app itself (no new capabilities or entitlements).

## Capabilities

### New Capabilities

None. This change is packaging and documentation; no behavior the app offers changes, so the change sets `skip_specs`.

### Modified Capabilities

None.

## Impact

- New: `scripts/package-ios.sh`, `altstore/source.json`.
- Edited: `README.md` (Packaging, Version and a new iPhone install section).
- `iosApp/module.xcodeproj` is regenerated by the toolchain and already committed; the script must not leave it modified (it overrides signing on the command line instead of editing project settings).
- No app code, database or dependency changes. `dist/` stays git-ignored; the IPA is attached to a GitHub Release by hand.
